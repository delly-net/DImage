# 项目文档整理压缩

此技能用于对 EAZY.RAG 知识库当前项目「小D图像」（项目 ID: 3）的项目信息中「执行计划」（executionSpecs）「注意事项」（executionNotes）「依赖关系」（dependencies）三份 Markdown 文档进行整理：读取三份文档，对文本长度超过 5000 字的文档进行优化压缩（整份判定 + 超长条款重点压缩，保留评级高的条款），经用户确认后写回项目信息。

## 使用方法

```
/eazy-rag-adjust
```

或在聊天中输入「整理压缩项目文档」触发。

## 功能

1. **获取项目信息**：调用 `mcp__eazy-rag__get_project`（projectId=3）→ 读取 executionSpecs（执行计划/执行规范）、executionNotes（注意事项）、dependencies（依赖关系）三份 Markdown 文档。
2. **长度判定**：对每份文档统计文本字符长度；**整份文档总长度超过 5000 字即判定需压缩整理**。
3. **压缩整理**：对需压缩的文档进行优化压缩：
   - **保留章节结构**：保留原文档的标题层级与章节框架，对超长条款重点精简；
   - **保留评级高的条款**：对条款按重要性评级，优先保留评级高（重要）的条款（技术栈/关键命令/权限约束/既有约定等），对评级低、冗余、重复的内容进行合并或删除；
   - 保持 Markdown 格式与术语一致，压缩后不改变文档含义。
4. **展示压缩差异**：向用户展示每份需压缩文档的压缩前后差异（原文长度 → 压缩后长度、保留与删除的条款说明）。
5. **用户确认后写回**：经用户确认后调用 `mcp__eazy-rag__update_project`（projectId=3，executionSpecs/executionNotes/dependencies=压缩后内容）写回项目信息；**未超过 5000 字的文档维持原样不更新**（update_project 仅更新传入的非空字段）。
6. **返回结果**：返回压缩整理结果（各文档原始/压缩后字符数、是否写回）。

## 注意事项

- 所有 MCP 调用必须携带正确的项目 ID：3。
- **所有步骤非注明需要询问或确认时，无需询问和确认，直接执行**。
- **写回项目信息前须经用户确认**：update_project 会覆盖项目 MD 字段，必须向用户展示压缩前后差异并经确认后方可写回。
- **整份判定 + 超长条款重点压缩**：每份文档总长度超 5000 字即判定需压缩；压缩时对超长条款重点精简，保留评级高（重要）的条款。
- **保留章节结构与关键条款**：压缩不得删除文档整体结构，仅合并/精简评级低、冗余、重复的内容；技术栈、命令、权限、约束等关键条款优先保留。
- **未超长的文档维持原样**：未超过 5000 字的文档不压缩、不更新，且不得传空值覆盖（update_project 仅更新传入的非空字段）。
- 本技能面向项目三份文档（executionSpecs/executionNotes/dependencies），不涉及任务执行计划（ExecutionPlan）正文。
